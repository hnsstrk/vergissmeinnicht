- TaskChampion-Replica im sandboxed App-Container, gestartet mit einem `VACUUM INTO`-Snapshot aus `~/.task/` (Taskwarrior 3.4.2). Schema-Migration 0|1 → 0|2 automatisch.

**UI**

- Hauptbereich: TaskListView mit ID-Chip, Description (Strikethrough für erledigte), Meta-Chips (Projekt/Tags/Due/Wait). Multi-Selection (Set-Binding). Sort-Picker (ID, Name, Angelegt, Fälligkeit, Projekt). Suche via `.searchable()`.
- Detail in eigenständigem Fenster (Doppelklick): Editor mit Description, Project, Tags, Due-Picker, Priority H/M/L; Annotations-Liste mit Add (Sheet) / Remove (Trash); read-only-Sektion UUID + Angelegt; Markdown im Annotation-Text. Toolbar mit „Erledigt"/„Reaktivieren" und „Speichern" (Cmd+S, atomar via `update_task_metadata`, Priority separat über `set_priority`).
- QuickCapture (Cmd+N) in MenuBarExtra und Toolbar: parst `+tag`, `project:`, `due:` (today/tomorrow/+Nd/+Nw/yyyy-MM-dd) und persistiert sie. Priority bleibt vorerst Vorschau.
- Kontextmenü auf TaskRow: Erledigt, Snooze („Morgen", „+3 Tage", „+1 Woche", „Snooze aufheben"), Detail öffnen, Bulk „Projekt zuweisen …" (bei Multi-Selection), Löschen (destruktiv).
- Swipe-Aktionen: links Erledigt (grün), rechts Löschen (rot).
- Drag & Drop: Task auf Projekt-Zeile = Project ersetzen, auf Tag-Zeile = Tag hinzufügen, auf Eingang = Project + alle Tags clearen.
- Toolbar (Hauptbereich): Sort-Picker, Neue Aufgabe, Erledigt (Cmd+D), Löschen (Cmd+⌫), Aktualisieren (Cmd+R), Sync-Status.
- Settings: drei Tabs (Allgemein, Sync-Server, Wartung). Allgemein: Sprache (System/DE/EN), Standardansicht beim Start, Standardsortierung, Bald-Fällig-Fenster (Stepper 1–60 Tage). Sync: URL/ClientID/Secret in Keychain + Test-Sync. Wartung: Legacy-Tasks-Reparatur.

## Architektur-Entscheidungen

- **AppContainer hält alle Tasks**, `pending` ist eine computed property. Counts/Filter-Logik wandert ins ViewModel.
- **`update_task_metadata` ist atomar** (Description/Project/Tags/Due); Priority + Wait separat geschrieben — bewusste Inkonsistenz, weil die atomar-Methode primär für den Repair-Lauf entstand.
- **Layout strikt 2-spaltig**: Sidebar | Tasks. Detail in eigenständigem Fenster — kein 3-Spalten-Splitter mit Inspector.
- **Working-Set-ID** kommt aus `replica.working_set().iter()` und wandert als `Option<u32>` in `TaskInfo`. Completed haben keine ID — beim Sort landen sie ans Ende.
- **Wartende Tasks** sind Pending mit `wait` in der Zukunft. Sie sind aus den meisten Filtern ausgeschlossen, aber unter "Wartend" und "Alle" sichtbar.
