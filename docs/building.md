# Building Vergissmeinnicht

End-to-end build instructions for the macOS app. Read [`README.md`](../README.md) first if
you want the overview; this document is the operational reference.

## Toolchain

| Tool | Version | Install |
|---|---|---|
| macOS | 14 Sonoma or later, Apple Silicon | — |
| Xcode | 16.x (Swift 6 toolchain) | App Store or `xcode-select --install` |
| Rust | stable (1.75+) | `brew install rust` or `rustup install stable` |
| XcodeGen | optional | `brew install xcodegen` — only to regenerate the xcodeproj from `project.yml` |

The committed `Vergissmeinnicht.xcodeproj` is hand-maintained at this point; you do
**not** need XcodeGen for a regular build.

## End-to-end build

```sh
git clone https://github.com/hnsstrk/vergissmeinnicht.git
cd vergissmeinnicht

# 1. Build the Rust core, generate Swift bindings, package the XCFramework
./scripts/build-macos.sh

# 2. Run the Swift Package tests (FFI roundtrip, metadata, write ops, sync errors)
swift test --package-path swift/VergissmeinnichtKit

# 3. Optionally run Rust tests
cargo test --manifest-path rust/Cargo.toml

# 4. Build the app
xcodebuild -project app/Vergissmeinnicht/Vergissmeinnicht.xcodeproj \
           -scheme Vergissmeinnicht \
           -configuration Debug \
           build

# 5. Launch
open ~/Library/Developer/Xcode/DerivedData/Vergissmeinnicht-*/Build/Products/Debug/Vergissmeinnicht.app
```

Or open the project in Xcode and press ⌘R:

```sh
open app/Vergissmeinnicht/Vergissmeinnicht.xcodeproj
```

## What `scripts/build-macos.sh` does

The script chains four steps:

1. **`cargo build --release -p vergissmeinnicht-core`** in `rust/` with
   `MACOSX_DEPLOYMENT_TARGET=14.0`. Produces:
   - `target/release/libvergissmeinnicht_core.a` — static lib for linking into the app
   - `target/release/libvergissmeinnicht_core.dylib` — used by `uniffi-bindgen` to
     read the symbol metadata
2. **`cargo run --bin uniffi-bindgen -- generate --language swift`** — generates
   the Swift wrapper, the C header, and the modulemap into `swift-bindings/generated/`.
3. **`xcodebuild -create-xcframework`** — packages the static lib plus the headers
   into `swift/VergissmeinnichtKit/VergissmeinnichtCoreFFI.xcframework`, which the
   SwiftPM package references as a binary target.
4. **Copy** the generated Swift wrapper into `swift/VergissmeinnichtKit/Sources/`
   so the package compiles against the regenerated FFI surface.

The XCFramework and the `swift-bindings/generated/` directory are gitignored —
they are regenerated by the script. The Swift wrapper checked into the repo
(`swift/VergissmeinnichtKit/Sources/VergissmeinnichtKit/vergissmeinnicht_core.swift`)
is the last build's output and **must be regenerated and committed when the FFI
surface changes**.

## When to rerun the build script

Run `./scripts/build-macos.sh` after:

- Any change in `rust/vergissmeinnicht-core/src/lib.rs` (new method, new type, signature change)
- `uniffi` dependency update in `Cargo.toml`
- `cargo clean` or switching the Rust toolchain target
- First clone of the repo

For pure Swift / app changes (views, view models, parsers) running `xcodebuild
build` (or ⌘B in Xcode) is enough.

## Test surface

| Suite | Command | What it covers |
|---|---|---|
| Rust unit tests | `cargo test --manifest-path rust/Cargo.toml` | smoke tests in `lib.rs` |
| `PingTests` | `swift test` | UniFFI roundtrip sanity (`ping()` returns `"pong"`) |
| `ReplicaRoundtripTests` | `swift test` | replica open / add / list |
| `WriteOperationsTests` | `swift test` | mark_done, modify, delete, add_annotation |
| `SyncTests` | `swift test` | sync error mapping with invalid URL |
| `MetadataTests` | `swift test` | `add_task_full`, per-field setters, `update_task_metadata`, atomic recurring follow-up, reactivate, annotation roundtrips |
| `DependencyTests` | `swift test` | `add_dependency` / `remove_dependency`, `is_blocked` / `is_blocking` derivation |

Expect **20 Swift package (FFI-layer) tests** to pass after a clean build.

### App-target tests

The app module **has a test target** (`VergissmeinnichtTests`, registered directly
in `Vergissmeinnicht.xcodeproj/project.pbxproj`). It builds against the host app via
`@testable import Vergissmeinnicht` and links `VergissmeinnichtKit` for `TaskInfo`
fixtures and a temp-dir `TaskStore`.

```bash
xcodebuild \
  -project app/Vergissmeinnicht/Vergissmeinnicht.xcodeproj \
  -scheme Vergissmeinnicht \
  -destination 'platform=macOS' \
  -derivedDataPath build/ \
  CODE_SIGNING_ALLOWED=NO \
  test
# CODE_SIGNING_ALLOWED=NO is fine here: tests don't produce a shipped bundle.
# Bundle-producing builds must keep ad-hoc signing — see "Common failures".
```

| Suite | What it covers |
|---|---|
| `ParserTests` | `QuickCaptureParser`, `RecurParser`, `DueDateParser` (pure functions) |
| `TaskListViewModelTests` | `SidebarFilter.matches` matrix (incl. `.today` scheduled branch, `.blocked` / `.blocking` / `.unblocked`), sort stability + tiebreakers, umlaut-aware search with operators / quoted phrases / AND logic |
| `AppContainerIntegrationTests` | `markDoneWithRecurrence` (interval, DST, month boundary), `renameProject` idempotency / partial failure, `repairLegacyTasks` idempotency / selective repair, against an isolated temp replica via the test-only `AppContainer(replicaURL:)` |

Expect **75 app-target tests** (incl. a one-line `SmokeTests` link check) to pass.

## Architecture overview

```
Apple-only:                        Cross-language:                      Rust:
┌────────────────────┐    Swift    ┌──────────────────────────┐  C ABI  ┌──────────────────┐
│ Vergissmeinnicht   │  ────────▶  │ VergissmeinnichtKit      │  ─────▶ │ vergissmeinnicht │
│   app target       │   `import`  │   SwiftPM package        │ static  │   -core (cdylib  │
│ (SwiftUI + AppKit) │             │   wraps the XCFramework  │  link   │   + staticlib)   │
└────────────────────┘             └──────────────────────────┘         └──────────────────┘
       Xcode build                    Both inputs come from                 cargo build
                                      scripts/build-macos.sh
```

Single source of truth for state: `AppContainer` holds `tasks: [TaskInfo]`. View
models hold derived UI state only. FFI calls happen in `Task.detached` so the
Rust `Mutex<Replica>` blocks a background thread, never the main actor.

## Common failures

- **`Cannot find type 'TaskInfo' in scope`** — Build script not run, or XCFramework
  stale. Run `./scripts/build-macos.sh` and rebuild.
- **Linker warning "object file was built for newer macOS version (15.x) than being linked (14.0)"** —
  Homebrew's `rust` builds `libstd` against the current macOS SDK; deployment
  target is 14.0. Cosmetic. Clean fix: switch to `rustup` with
  `-Z build-std=std,panic_abort` to rebuild stdlib against the deployment target.
- **`SQLite busy` / `Replica locked` at launch** — another instance still running.
  `pkill Vergissmeinnicht` or `killall Vergissmeinnicht`.
- **App shows "Initialisierung fehlgeschlagen"** — replica path inaccessible
  (sandbox permission, disk full). The `InitErrorView` has a "Retry" button;
  inspect `~/Library/Containers/de.hnsstrk.vergissmeinnicht/Data/Library/Application Support/`
  manually if the retry keeps failing.
- **uniffi-bindgen "no library found"** — `cargo build` was run in debug mode but
  the script expects `target/release`. Run the script clean: it builds release
  itself.
- **Code signing failures in Xcode** — ad-hoc signing is on by default. If Xcode
  prompts for a team, set "Signing Certificate" to "Sign to Run Locally" in the
  target's Signing & Capabilities tab.
- **App data lands in `~/Library/Application Support/vergissmeinnicht/` and
  `~/Library/Preferences/` instead of the container** — the bundle was built
  unsigned (e.g. with `CODE_SIGNING_ALLOWED=NO`). The sandbox is granted via the
  `com.apple.security.app-sandbox` entitlement, which is only embedded into the
  binary during code signing; an unsigned (merely linker-signed) build runs
  *without* the sandbox and uses different preference/replica paths than a
  signed one. For that reason every bundle that actually gets run or shipped
  (`scripts/install-local.sh`, the CI debug artifact, the release workflow)
  keeps ad-hoc signing enabled. Verify with
  `codesign -d --entitlements - Vergissmeinnicht.app` — the output must contain
  `com.apple.security.app-sandbox`.

## Replica location and reset

The app's replica lives in the sandbox container:

```
~/Library/Containers/de.hnsstrk.vergissmeinnicht/Data/Library/Application Support/vergissmeinnicht/replica/
```

This path assumes a (at least ad-hoc) signed build — see the unsigned-build
entry under [Common failures](#common-failures) for the unsandboxed fallback
paths.

To reset to a clean state:

```sh
killall Vergissmeinnicht 2>/dev/null
rm -rf ~/Library/Containers/de.hnsstrk.vergissmeinnicht/Data/Library/Application\ Support/vergissmeinnicht/replica/
```

The app will create a fresh empty replica on next launch. See
[`backup-and-restore.md`](backup-and-restore.md) for restore from snapshot,
including how to seed from a Taskwarrior `VACUUM INTO` dump.

## CI

GitHub Actions runs build + tests on push and pull requests against `main`. See
[`.github/workflows/ci.yml`](../.github/workflows/ci.yml). No release artifacts
are uploaded: distribution requires a paid Apple Developer ID and Notarization,
which is on the [backlog](../README.md#status), not in the CI pipeline.
